01Lexing et parsing (rappel)

  • Lexing : texte → liste de tokens.
  • Parsing : faire comprendre le texte au programme.
  • Le lexing mâche, le parsing digère.
  • Résultat du parsing : une structure de données, souvent un arbre syntaxique.
  • Dans Minimake, tu as écrit ce parseur toi-même.
  • Ici, une bibliothèque le fait pour toi : tu exploites l'arbre qu'elle te rend.
"energie": 12.5   ─ lexer ─▶   STRING(energie)  COLON  NUMBER(12.5)   ─ parser ─▶   🌳 nœud {clé:"energie", nombre:12.5}

02Données structurées & schéma

  • Donnée structurée : organisée selon un modèle explicite.
  • Schéma / data model : le document qui décrit ce modèle.
  • Il dit, pour chaque champ : nom, type, signification (et contraintes).
  • Écrit formellement (ex. JSON Schema), il permet la validation automatique.
  • On valide avant d'exploiter : on ne fait jamais confiance à l'entrée.

03Mêmes données, formats différents

  • Même structure, plusieurs syntaxes.
  • CM : CSV, JSON, YAML, XML, TOML, INI, SQL.
  • Règle d'or du CM : utilise une bibliothèque existante si tu peux.

04JSON en 30 secondes

  • 6 types : objet {}, tableau [], string, nombre, booléen, null.
  • Clés toujours entre guillemets doubles.
  • Pas de virgule finale, pas de commentaires, pas de '.
  • Un seul type nombre (pas de int/float séparés).
  • Un objet = clés → valeurs, un tableau = liste ordonnée.

05cJSON : ce que le parseur te rend

  • cJSON_Parse lit tout le texte et rend la racine d'un arbre.
  • Chaque nœud est un cJSON *.
  • Les enfants d'un objet/tableau = liste chaînée (child, puis next).
  • Conséquence : accéder au i-ème élément coûte O(i).
typedef struct cJSON {
    struct cJSON *next, *prev;  // frères (liste chaînée)
    struct cJSON *child;        // 1er enfant (objet / tableau)
    int type;                  // cJSON_String, cJSON_Number, ...
    char *valuestring;         // si string
    int valueint;              // si nombre (TRONQUÉ, à éviter)
    double valuedouble;        // si nombre ✔
    char *string;              // la CLÉ si le nœud est dans un objet
} cJSON;
Compile avec -lcjson et inclus <cjson/cJSON.h>.
Installation : sudo apt install libcjson-dev

06Lire du JSON : les 6 étapes

  • 1. Lire le fichier dans un buffer.
  • 2. cJSON_Parse(buf) → racine, ou NULL si JSON invalide.
  • 3. Naviguer : cJSON_GetObjectItemCaseSensitive, cJSON_ArrayForEach.
  • 4. Vérifier le type : cJSON_IsString, IsNumber, IsArray…
  • 5. Lire la valeur : ->valuestring, ->valuedouble.
  • 6. cJSON_Delete(racine) : libère tout l'arbre.

Étape 1 · lire un fichier entier

static char *read_file(const char *path)
{
    FILE *f = fopen(path, "rb");
    if (!f)
        return NULL;
    fseek(f, 0, SEEK_END);
    long size = ftell(f);         // taille du fichier
    rewind(f);
    char *buf = malloc(size + 1);  // +1 pour le '\0'
    if (!buf) { fclose(f); return NULL; }
    size_t n = fread(buf, 1, size, f);
    fclose(f);
    buf[n] = '\0';                 // cJSON_Parse veut une chaîne C
    return buf;
}

Étapes 2 → 6 · exemple complet

char *text = read_file(argv[1]);
if (!text) { fprintf(stderr, "Erreur : lecture\n"); return 1; }

cJSON *root = cJSON_Parse(text);
free(text);                           // l'arbre est indépendant du texte
if (!cJSON_IsArray(root)) {             // IsArray(NULL) == false : couvre aussi l'échec
    fprintf(stderr, "Erreur : JSON invalide\n");
    cJSON_Delete(root);                // Delete(NULL) ne fait rien : OK
    return 2;
}

const cJSON *m;
cJSON_ArrayForEach(m, root) {
    const cJSON *nom = cJSON_GetObjectItemCaseSensitive(m, "nom");
    const cJSON *en  = cJSON_GetObjectItemCaseSensitive(m, "energie");
    if (!cJSON_IsString(nom) || !cJSON_IsNumber(en))
        continue;                         // champ absent ou mauvais type
    printf("%s : %.2f\n", nom->valuestring, en->valuedouble);
}
cJSON_Delete(root);

07Écrire du JSON

  • cJSON_CreateObject() / cJSON_CreateArray() créent un nœud.
  • cJSON_AddStringToObject, AddNumberToObject, AddBoolToObject… ajoutent un champ.
  • cJSON_AddArrayToObject(obj, "k") crée et ajoute un tableau, et te le rend.
  • cJSON_AddItemToArray(arr, item) : l'arbre devient propriétaire de item.
  • Donc un seul cJSON_Delete sur la racine suffit.
  • cJSON_Print (indenté) / cJSON_PrintUnformatted (une ligne) allouent → free.
cJSON *root = cJSON_CreateObject();
cJSON_AddStringToObject(root, "station", "Kepler-7");
cJSON *crew = cJSON_AddArrayToObject(root, "equipage");

cJSON *p = cJSON_CreateObject();
cJSON_AddStringToObject(p, "nom", "Ada");
cJSON_AddNumberToObject(p, "age", 41);
cJSON_AddItemToArray(crew, p);      // p appartient maintenant à crew

char *s = cJSON_PrintUnformatted(root);
puts(s);                            // {"station":"Kepler-7","equipage":[{"nom":"Ada","age":41}]}
free(s);
cJSON_Delete(root);

08CSV en C

  • Pas besoin de lib exotique : fgets + strtok_r suffisent pour un CSV simple.
  • 1re ligne = en-tête (noms des colonnes) → à sauter.
  • Le CM met des espaces après les virgules : CMake, prog-206-l-01 → il faut trim.
  • Windows : lignes en \r\n → le trim enlève aussi le \r.
  • strtok fusionne les séparateurs : a,,b donne 2 champs, pas 3 !
  • Champs entre guillemets avec virgules dedans → là, une vraie lib (libcsv) est justifiée.
static char *trim(char *s)
{
    while (isspace((unsigned char)*s))
        s++;
    char *end = s + strlen(s);
    while (end > s && isspace((unsigned char)end[-1]))
        end--;
    *end = '\0';
    return s;
}

char line[1024];
int header = 1;
while (fgets(line, sizeof(line), f)) {
    char *l = trim(line);
    if (*l == '\0') continue;              // ligne vide
    if (header) { header = 0; continue; }   // en-tête
    char *save = NULL, *fields[4];
    int n = 0;
    for (char *t = strtok_r(l, ",", &save); t && n < 4; t = strtok_r(NULL, ",", &save))
        fields[n++] = trim(t);
    if (n != 4) continue;                  // ligne malformée
    /* fields[0] = nom, fields[3] = oxygene ... */
}
strtok_r n'est pas C99 pur : mets #define _POSIX_C_SOURCE 200809L avant les includes.

09Erreurs et mémoire

  • Messages d'erreur → stderr. Résultats → stdout.
  • Code de retour : 0 = succès, autre = erreur (respecte la consigne à la lettre).
  • Tout retour de fopen, malloc, cJSON_Parse se compare à NULL.
  • Un champ peut manquer → GetObjectItem rend NULL.
  • Un champ peut avoir le mauvais type → toujours cJSON_Is* avant ->value….
Qui alloue ?Qui libère ?
read_file (malloc)free(text) — dès après le parse
cJSON_Parse / cJSON_Create*cJSON_Delete(root) une seule fois
Nœud ajouté via AddItemTo…Personne : l'arbre parent s'en charge
Nœud obtenu via GetObjectItemJamais (il appartient à l'arbre)
cJSON_Print*free(str)
fopenfclose (aussi dans les chemins d'erreur !)

10Optimisation (là où on perd des points)

✖ O(n²) — chaque GetArrayItem(i) reparcourt la liste depuis le début : 
for (int i = 0; i < cJSON_GetArraySize(arr); i++) {   // GetArraySize : O(n) À CHAQUE TOUR
    cJSON *e = cJSON_GetArrayItem(arr, i);           // O(i)
}
✔ O(n) — on suit les next : 
cJSON *e;
cJSON_ArrayForEach(e, arr) { ... }
  • Max / min / somme : un seul passage, pas de tri.
  • Init du max avec la 1re valeur, pas 0 (valeurs négatives !).
  • Récupère chaque champ une fois dans une variable, pas de GetObjectItem répétés.
  • Pas de strlen dans une condition de boucle.
  • Libère le texte JSON dès que l'arbre est construit.
